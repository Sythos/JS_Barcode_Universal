# Sythos Barcode Suite — plan and status

A from-scratch barcode read/write suite. **MIT, © Sythos, 100% original JavaScript, zero runtime dependencies.**

---

## 0. Ground rules

### 0.1 Originality — the rule that protects the licence

> **No source code and no constant table from any other barcode implementation enters this project — under any licence, permissive or otherwise.**
> Not a line, not a value, not a table "that is only data anyway".

Symbologies are implemented from published descriptions of the formats — which are systems and facts, not works of authorship — and from constant tables generated by this project's own scripts wherever a table is derivable rather than arbitrary.

### 0.2 Where other libraries may appear

The line is **invoke vs. read**:

| | |
|---|---|
| Running an independent implementation during **testing**, comparing its output to ours | allowed |
| Reading its source, or lifting a table from it, into this project | **never** |

Such outputs are facts about a published symbology, not creative expression. Comparing against them creates no derivative work — and an implementation that independently agrees with several unrelated ones, byte for byte, is evidently correct *and* evidently not a copy of any of them. That is how originality gets demonstrated rather than merely asserted.

No third-party barcode code is a runtime dependency; none of it ships. See `LICENSE` §2 and `NOTICE.md`.

### 0.3 Round-trip tests are not proof of correctness

The failure mode that kills projects like this: encode→decode is **symmetric**. A wrong Reed–Solomon generator, a transposed mask table, or a flipped bit-placement order applied in *both* directions passes every round-trip test while producing symbols no real scanner can read.

So four other mechanisms carry the weight — see `NOTICE.md`, "How correctness is verified". Two are already earning their keep:

- **QR's table identity.** For all 160 version/ECC combinations, the sum of data and ECC codewords across every block must equal the capacity computed *independently* from module geometry. One mistyped digit anywhere in that table breaks the identity. It currently passes clean.
- **Prime-field Reed–Solomon.** Correction is tested to the theoretical limit in all seven fields. A decoder that inlines `^` for field addition passes every binary field and fails only GF(929) — which is exactly how PDF417 silently breaks.

The decisive mechanism is still the last one: **a format is not finished until a symbol it produced has been read by a device this project did not write.** `examples/create.html` exists partly to make that a thirty-second check with a phone.

### 0.4 Language, platform, licensing hygiene

- **Plain JavaScript (ESM)** with JSDoc types. No TypeScript source; `.d.ts` generated by `tsc --allowJs`.
- **Syntax floor: iOS Safari 15.** No `Array.prototype.at`, no top-level `await`, no `Object.groupBy`. `OffscreenCanvas`, WebGL2 and WebGPU are feature-detected, never assumed — the 2D canvas path always exists, so nothing is unreachable on an older device.
- **Every `.js` file carries the full MIT licence text**, naming Sythos as sole copyright holder. Nothing is taken from elsewhere, so there is no upstream licence to carry and no co-author to credit. The header tool reads the licence body out of `LICENSE` so the two cannot drift, is idempotent, and never touches a file whose header is not its own — so a file that ever *did* incorporate third-party work would keep that work's header and be logged in `NOTICE.md`.
- The published repository contains only what is needed to *use* the library: `src/`, `bundle/`, `examples/`, `licenses/` and the documentation. Test suites, build tooling and local assistant artefacts are developed alongside but not published. Consequence: **`bundle/` is committed**, because the tool that builds it is not — a fresh clone must find it ready. `examples/` is canonical and is not duplicated in the development workspace.

The `GaloisField` deliberately serves GF(2⁴) through GF(2¹²) **and the prime field GF(929)** — so PDF417 needs no second implementation when it lands. Addition, subtraction and negation are methods, never an inlined `^`.

### Remaining

**P5 — the remaining 2D formats**, in descending value / ascending pain:

- **PDF417** — GF(929), already supported by the core. 3 cluster tables × 929 codewords. **Spike this before anything else in P5:** test whether the cluster table is generatable by enumerating all 17-module, 8-element patterns with element widths 1–6, filtering on `cluster = (b1−b2+b3−b4) mod 9 ∈ {0,3,6}`, and checking it yields exactly 929 patterns per cluster — then cross-check a handful of codeword→pattern mappings, because the count alone does not prove the *ordering*. If generation fails, the table must be transcribed from documentation, and that changes the effort by an order of magnitude. Better to learn that on day two than in month four.

**Long tail, tiered by shared machinery** — this is what makes scope cuttable intelligently:

- *Nearly free given what exists:* Telepen, industrial/IATA 2-of-5 variants. Plus the **postal family** (POSTNET, PLANET, IMb, RM4SCC, KIX, Australia Post, Japan Post) — all 4-state height-modulated, sharing **one** engine.
- *Moderate, reuses existing 2D machinery:* Micro QR and rMQR (own version tables, QR's core), MicroPDF417, Codablock-F and Code 16K (stacked Code 128).
- *Each effectively its own project:* MaxiCode (hexagonal grid, own detector), DotCode, Han Xin, GS1 Composite, and the **DataBar family** (14 / Limited / Stacked / Expanded — notoriously fiddly).

**Not implemented, deliberately** — proprietary, or status too unclear to redistribute an implementation with confidence: Digimarc Barcode, VeriCode, DataGlyphs, Snowflake, ShotCode, Microsoft Tag, Bokode, Softstrip, Ultracode. Listed with reasons in `LICENSE` §6.

**Other work:**
- GPU binarization for camera frames (see §2) — the one place GPU would genuinely change the numbers.
- WebGPU renderer alongside the WebGL2 one.
- Aztec robustness follow-through: ZXing and zxing-cpp black-box vectors, plus a real-photo corpus with tracked pass-rate. The current detector handles rotation, inversion and quadrilateral sampling; severe perspective remains an enhancement rather than a guaranteed capability.
- Real-photo corpus with a **tracked pass-rate, not pass/fail** — a binary gate hides a regression from 94% to 71%.
- `[TO VERIFY]` markers in `LICENSE` §3–5 cleared with citations, logged in `NOTICE.md`. Priority: **rMQR** (standardised 2022 — do not assume DENSO WAVE's older QR position covers it).

## 2. On GPU acceleration

WebGL2/WebGPU accelerate **drawing** a barcode, not **computing** one. Worth stating plainly, because "GPU barcode generation" naturally suggests the latter.

Encoding is sequential integer work — Reed–Solomon polynomial division, mask penalty scoring, zig-zag bit placement — each step depending on the last, which is precisely the shape a GPU cannot exploit. A full QR encode is well under a millisecond on the CPU, less than a compute-shader dispatch and readback would cost. Moving it to the GPU would make it slower, and no amount of engineering changes that.

Where the GPU genuinely earns its place:

1. **Drawing** large symbols, or many per frame, straight into a canvas. *(Shipped: WebGL2.)*
2. **Reading** — per-frame greyscale conversion and block statistics over a 1080p/4K camera frame. Embarrassingly parallel, and the actual bottleneck in camera scanning. *(Planned.)*

Encoding stays on the CPU because that is the correct engineering answer, not because of a missing feature.

## 3. Effort, honestly

| Phase | Difficulty |
|---|---|
| Core primitives | moderate — the highest-leverage code in the project |
| 1D writers | easy, mechanical |
| 1D readers | moderate; photo robustness is the long tail |
| QR | **hard** — the centrepiece |
| Data Matrix / PDF417 / Aztec | **hard**; PDF417's detector is the single hardest piece |
| Renderers, bundler, examples | easy |

**Core + 1D + QR is already a genuinely useful library.** P5 roughly doubles the effort for formats most projects never touch. "All formats" is a multi-month undertaking; the tiering above is what makes it stoppable at any point without leaving something half-built.

## 4. Open questions

1. **Package name** — settled: the package publishes as the scoped **`@sythos/js_barcode_universal`**, with `publishConfig.access: "public"` (scoped packages default to restricted). Deliberately descriptive: naming a product after a trademark (QR Code®, Aztec Code, MaxiCode) is the one thing to avoid, since those marks do not restrict *implementing* the symbologies but do constrain branding.
2. **Browser build** — ESM + IIFE ship today. Worth adding a minified variant?
3. **Camera helper** — `read.html` has a working `getUserMedia` loop with the iOS quirks handled (`playsinline`, user-gesture `play()`, `facingMode: 'environment'`). Promote it to a library export (`scanFromCamera(video, onResult)`), or leave it as example code?
